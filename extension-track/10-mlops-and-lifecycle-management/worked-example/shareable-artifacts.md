# Worked Example: Shareable Artifacts

## Goal

Provide another team with the promoted workflow package and enough metadata to rerun or audit it.

## What To Share

Share only promoted artifacts:

- promoted manifest
- pinned config used for promoted run
- model or adapter artifact
- evaluation summary report
- release notes with intended use and limits

Do not share draft outputs as if they were final deliverables.

## Suggested Storage Split

- project workspace: active and reviewed experiments
- LUMI-O: promoted package and reports for cross-team access

## Team Handoff Record

For each shared package include:

- owner and reviewer
- creation and review date
- source run ID
- retrieval path
- contact for incident or rollback
